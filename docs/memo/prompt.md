## work_flow_2

2. GitHubのPRレビューでユーザーとbotからの修正依頼を確認する。修正依頼があった場合は、内容を確認して修正を行い、PRを更新する。

## workflow_review_for_issue

1. 作業開始時に、ルートの `GOAL.md` と Github Issue を一つ選択し、その Issue の妥当性を判断するために必要な範囲で、リポジトリの構成、関連する実装、ドキュメント、既存 Issue 等を確認する。
2. Issue が、現在のリポジトリから `GOAL.md` のゴールへ進むための作業として妥当か確認する。
   - 現在のリポジトリとゴールとの差分に基づいた内容になっているか
   - ゴールの達成に実際に寄与する内容か
   - 他に優先して行うべき作業があるにもかかわらず、この Issue が選ばれていないか
   - 現在の状態から実施する順序として適切か
3. Issue 自体の品質を確認する。
   - やることが明確か
   - 完了条件が明確か
   - 粒度が適切か
   - 余計・重複な作業がないか
4. 問題がある場合は、問題点、その理由、修正案を Issue にコメントする。
5. 問題がない場合は、その旨を Issue にコメントする。
6. Issue のレビューでは、実装やファイル変更を行わない。

## workflow_review_for_PR
1. 作業開始時に、ルートの `GOAL.md` と Github PRを一つ選択し、関連する Issue および、PR の妥当性を判断するために必要な範囲で、リポジトリの構成、関連する実装、ドキュメント等を確認する。
2. PR が、関連する Issue の内容を適切に実現しているか確認する。
   - Issue で求められている内容が実装されているか
   - Issue の完了条件を満たしているか
   - Issue の範囲を超えた不要な変更が含まれていないか
3. PR 自体の品質を確認する。
   - 実装内容が正しいか
   - 既存の実装との整合性が保たれているか
   - 不要・重複した実装がないか
   - 必要なテストや検証が行われているか
   - 既存の機能を壊していないか
4. 問題がある場合は、問題点、その理由、修正案を PR にコメントする。
5. 問題がない場合は、その旨を PR にコメントする。
6. PR のレビューでは、コード、設定、ドキュメント等の変更を行わない。
