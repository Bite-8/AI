# 開発用proxyの初回実行構成と見積もり

調査日: 2026-09-08。状態: 提案。モデル推論、GPUインスタンス起動、学習は未実施。

## 推奨構成

開発用proxy候補のQwen3.5-0.8Bを、東京リージョンの `g6.xlarge`（NVIDIA L4、ホストRAM 16 GiB）で短時間動かす。これはGoalで比較対象にする高性能reference baselineの実行計画ではない。開発用 `t2.micro` は変更せず、実験機を分ける案とする。初回はテキスト入力のみ、量子化なし、batch size 1、入力上限512トークン、生成上限128トークン、固定入力3件とする。推論開始前に入力長を検査する。

この選択は、比較した候補のうち、最近のハイブリッド構造を小さく調べるという目的に基づく。最上位性能・最安・最速という評価ではない。L4環境でBF16推論を試す計画だが、ドライバ・PyTorch・カーネル互換性と実メモリは実機で確認する。公式インスタンス仕様表のGPUメモリ表記は22 GiB。

- proxy第一候補: `Qwen/Qwen3.5-0.8B`（revisionは[`docs/decisions/baseline-selection.md`](../decisions/baseline-selection.md)に固定）。Gated DeltaNetとAttentionの内部状態を低コストで追う。
- 構造理解用の代替: `Qwen/Qwen3-0.6B` + `g4dn.xlarge`。より単純なAttention中心の構造を調べる場合に使う。T4ではFP16を候補とし、BF16環境との数値比較を同一条件扱いにしない。
- 拡張候補: `Qwen/Qwen3.5-4B`。0.8Bで実行基盤ができた後に検討する。最初から複数モデルを動かす費用はかけない。

CPUのみの `m7i.large` も時間単価では安い。ただし推論時間・改変後の評価時間を測っていないため、総費用で優位とは判定しない。今回のGPU案は将来の内部改変・学習実験へつながる実行経路を確認するための提案であり、小型モデルの生成にGPUが必須という意味ではない。

## 料金の根拠

AWS公式の[東京リージョン価格CSV](https://pricing.us-east-1.amazonaws.com/offers/v1.0/aws/AmazonEC2/current/ap-northeast-1/index.csv)を取得し、Linux / Shared / OnDemand / Pre Installed S/W=NA / CapacityStatus=Usedで抽出した。該当行のEffectiveDateは2026-09-01。生の該当行と条件は [価格記録](./evidence/aws-prices-2026-09-08.json) に保存した。Spot、割引契約、無料枠、税は適用していない。

| 候補 | 用途 | USD/時 | 2時間の計算料金 |
|---|---|---:|---:|
| m7i.large | CPU、RAM 8 GiB | 0.1302 | 0.2604 |
| g4dn.xlarge | T4、RAM 16 GiB | 0.7100 | 1.4200 |
| g6.xlarge | L4、RAM 16 GiB、第一候補 | 1.1672 | 2.3344 |
| g5.xlarge | A10G、RAM 16 GiB | 1.4590 | 2.9180 |

GPUの種類・メモリは[AWS仕様表](https://docs.aws.amazon.com/ec2/latest/instancetypes/ac.html)を参照。g5は今回の比較では時間単価が高いため保留とし、速度あたり費用で劣るとまでは結論しない。割当上限・対象AZの空きは未確認。

### 初回2時間の試算

見積もり条件: Linux、追加ソフトウェア料金のないイメージ、GPU起動2時間以内、gp3合計50 GBを24時間保持、標準のIOPS/throughput、公衆IPv4を1個2時間使用。NAT Gatewayや有料VPC endpointは追加しない構成を想定する。AMIの最小ディスク容量・実ネットワーク構成によって再見積もりする。

| 項目 | g6.xlarge案 | g4dn.xlarge案 |
|---|---:|---:|
| 計算資源2時間 | $2.3344 | $1.4200 |
| gp3 50 GBを1日保持（30日月で概算） | $0.1600 | $0.1600 |
| IPv4 1個を2時間 | $0.0100 | $0.0100 |
| 小計 | **$2.5044（約$2.51）** | **$1.5900** |

gp3は東京で$0.096/GB-month、IPv4は[公式VPC料金](https://aws.amazon.com/vpc/pricing/)の$0.005/時を使用した。為替変動を混ぜないためUSDで比較する。

この小計は条件付き試算であり、請求上限ではない。税、外向き通信、ログ・結果の別保存先、既存EC2・既存契約費は含まない。初回は重みのダウンロードと小さい結果ファイルの取得を想定するが、通信経路と実使用量の確認が必要。セットアップやダウンロードの時間も2時間枠に含め、失敗したら枠内で停止して持ち帰る。GPUを停止してもEBS費用は続く。50 GBを1か月残すと$4.80になる。保持期間終了時に結果を退避し、実験用ボリュームの削除を含む終了手順を決める。

比較の参考として、g6を月4回、毎回2時間、EBS 50 GBを月間保持し、IPv4を合計8時間使用する条件なら $9.3376 + $4.80 + $0.04 = **$14.1776/月**。月額予算への提案材料であり、未計上費用は初回試算と同じ。

## 起動前に準備する実装と確認

1. 固定revisionを読む推論入口を `ai_research/` に実装する。tokenizer/chat template、dtype、生成条件、入力データを設定として保存する。推論入口は実装済み。GPU実機での読込・生成は未検証。
2. PyTorch・Transformersの主要依存版とCUDA配布案は[`docs/research/RUNNING.md`](../research/RUNNING.md)に記載した。実機で組合せを検証する。調査したTransformers commitを、そのまま動作確認済み依存版とは扱わない。
3. 日本語の短い質問、短文要約、簡単な計算の3件を開発用入力として固定する。これは疎通確認であり、能力改善の研究評価には使わない。
4. 起動から2時間で停止する仕組み、失敗時の停止、終了状態の外部確認、結果の回収を準備する。プロセスのタイムアウトだけでEC2料金は止まらない。
5. GPU割当・候補AZ・IAM権限・AMI・50 GBで足りるかを確認する。既存ネットワークを確認して通信・IP費用を補正する。
6. 構成、見積もり、停止・保存手順が揃ってから、初回の有料起動についてユーザーに提示する。現在は起動の承認待ちではなく、準備段階。

## 初回の到達条件

- 固定版のモデルを無変更で読み込める。
- 3件の入力について入力・出力トークン数、生成テキスト、終了理由を保存できる。
- 読込時間と生成時間を分けて測り、GPUピークメモリと環境・設定・コード版を記録できる。
- 同じ条件を再実行して出力差を確認できる。完全一致を仮定せず差も記録する。
- 結果を回収し、EC2の停止を確認できる。

性能改善や脳原理の導入は次段階。初回に分かるのは、開発用proxyを再現して動かすための実費と実行条件である。この結果だけでは高性能reference baselineの再現やGoalの改善を示さない。

## ネットワークと権限の確認範囲

この編集環境からHugging Face・GitHub・AWS公開料金表へのHTTPS取得と、IMDSv2のinstance-type / placement/region取得に成功した。全宛先・全プロトコルの疎通を検証したものではない。EC2の起動・停止・割当照会などのIAM権限は未検証であり、アウトバウンド通信成功とは分けて扱う。


### 追加確認: 現在の接続経路（2026-09-08）

- IMDSv2で現在のEC2にパブリックIPv4が1個割り当てられていることを確認した。具体的なIP・アカウントID・リソースIDは本書に保存しない。
- OSのデフォルトルートはVPC内のルーター向き。HTTP_PROXY / HTTPS_PROXY / ALL_PROXYは未設定。IMDSのIPv6アドレス取得はHTTPエラーで、IPv6経路は確認できなかった。
- 現在のロールで `ec2:DescribeRouteTables`、`ec2:DescribeSubnets`、`ec2:DescribeNatGateways` を実行したが、すべて `UnauthorizedOperation`。エラー理由は該当操作を許可するidentity-based policyがないこと。ネットワーク変更は実施していない。
- したがって、現在のサブネットのInternet Gateway向けルート、NAT Gatewayの有無、パブリックIPの自動割当設定は未確認。パブリックIPv4付きの直接接続は候補だが、実際の経路と断定しない。

パブリックIPv4はあらゆる構成で必須ではないが、IPv4でInternet Gatewayへ直接出る構成では必要になる。[AWSのInternet Gateway説明](https://docs.aws.amazon.com/vpc/latest/userguide/VPC_Internet_Gateway.html)を参照。現在のEC2に付いているIPv4を、新規実験機が自動的に共有できるわけではない。

このため見積もりのIPv4 1個・2時間=$0.01は暫定的に維持する。既存の外向き経路が使えると確認できた場合に修正する。今回の短時間試行だけを目的に新しいNAT Gatewayを追加する案は採らない。パブリックIPv4の割当と、インバウンドのサービス公開は別の設定である。

AWS側の確認を続けるには、実行ロールで上記3つのDescribe操作を許可するか、管理者が対応する設定を確認する必要がある。起動・停止の権限は今回試していないため、不足しているとも保有しているとも断定しない。

推論コマンドの実装・実行手順は [RUNNING.md](../research/RUNNING.md) を参照する。費用は概算として扱い、ネットワーク費用の詳細化を実装作業の前提にはしない。
