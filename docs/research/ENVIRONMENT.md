## 別の実行環境での確認方法

リポジトリルートでPython 3.10以上を使い、追加パッケージなしで実行できる。

```bash
python3 -m ai_research.environment
```

ファイルに保存する場合:

```bash
python3 -m ai_research.environment --output logs/ai_research/environment-research.json
```

同名ファイルは上書きしない。再測定時は別名を使う。モデル保存先が別ファイルシステムなら `--disk-path` にその既存パスを渡す。`logs/ai_research/` はgit管理外であり、共有する判断根拠は本書へ転記する。

このコマンドはパッケージの版を調べるが、importやGPU演算の成功は保証しない。NVIDIA以外のアクセラレーターも別途確認する。Linux以外のメモリ取得分岐は用意しているが、現時点の実機確認はこのLinux環境のみ。

IMDSへの問い合わせはこの環境調査で個別に行った。汎用の環境確認コマンドはIMDSにアクセスせず、インスタンスタイプも自動収集しない。

## コストを判断する進め方（2026-09-08）

ユーザー申告: Codex Plus・Claude Proは契約・導入済み。既存契約を使って開発する。契約の利用枠・追加課金条件は本書では検証しておらず、無制限利用やAPI利用料込みとは仮定しない。

- 開発では小さな作業単位で実装し、重要なコード差分・実験条件にレビューを集中する。両エージェントに同じ調査・編集を常時二重実施させない。
- コスパは「再現可能な比較結果を一つ得るまでの総費用と時間」で判断する。時間単価だけでモデル・計算機を選ばない。
- 最初の有料試行は、モデル読込と短い固定入力の生成・記録までを対象とする。初回の起動時間枠は最大2時間を提案するが、これは所要時間の実測値でも支出承認でもない。
- 起動前に、東京リージョンで候補GPUのLinux On-Demand料金、割当・空き、モデルの必要メモリ、保存領域を確認する。GPUを必要時間だけ使い、開発用EC2から分ける構成を暫定案とする。
- 初回は環境構築の不確定要素を減らすためOn-Demandを比較の基準とする。中断・再開可能な実験基盤ができたらSpotも比較する。Spotの割引率・供給・中断頻度は固定値と扱わない。
- 実験終了・時間上限での停止手段と結果保存先を用意し、停止を確認する。停止後の保存費用も記録する。この停止機構はまだ未実装。

初回見積もりは次の式で作る:

`計算機の時間単価 × 起動時間（セットアップ・取得・評価・待機を含む） + 保存容量に対する保持期間分の費用 + 通信・IP等の費用`

円換算する場合は換算日・為替・税の扱いを明記する。候補インスタンスの公式単価を取得し、初回案は [FIRST_RUN_PLAN.md](../experiments/FIRST_RUN_PLAN.md) に記録した。実費は未測定。実測後に「1実験あたり費用 × 予定回数 + 固定費」から月額を提案する。

料金体系の確認元（2026-09-08）:

- [EC2 On-Demand料金](https://aws.amazon.com/ec2/pricing/on-demand/): 長期契約なしの時間・秒単位の課金。対象OS等の条件を確認して見積もる。
- [EC2の状態と課金](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/ec2-instance-lifecycle.html): 停止後もEBSなどの資源には費用が残る。
- [Spotの中断](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/spot-interruptions.html): 余剰容量を利用するため中断に対応する必要がある。
